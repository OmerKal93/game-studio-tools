# Verification: e2e, screenshots, render review

- **Real frame rate needs headless Chromium.** A browser-automation tab inside another tool can run requestAnimationFrame at about 1.5 fps, so physics and movement cannot be judged there. Use Playwright headless with `--use-angle=d3d11 --ignore-gpu-blocklist`, with real key holds (not synthetic keydown events).
- **An e2e hook.** Have the game expose an opt-in hook (for example `?e2e=1` sets `window.__gameTest` with a `metrics` object) so a headless script can drive it and read numbers. The e2e writes a results file and screenshots outside the repo. Done when every check is PASS with 0 console errors. Read the PASS lines' numbers, not just the count.
- **An e2e lock:** anything that runs the e2e or a headless capture in the same working copy goes through `node tools/locked-run.mjs <lockDir> -- node scripts/...` (run it in the background; it polls every 30 s and releases only a lock it took). `ue-run.mjs` can yield to the same lock with `--yield-lock`. If several agents share a scratch folder, keep your scripts and build trees in a subfolder named after your task.
- **Parallel agents:** only one build may own the client output folder. Give each other agent its own `--outDir` and port, and let one integrator run the full e2e.
- **Render review:** a model, clip or scene change is verified by looking at rendered frames yourself (contact sheet or a few frames per clip), saved next to the e2e screenshots. Contact sheet tool: `node tools/render-sheet.mjs <model.glb> <outDir> [--clips Idle_A,Walking_A] [--frames 8] [--focus mixamorigHead] [--ref ref.glb --ref-scale 1] [--tint Mat=#hex] [--yaw 180]`: per clip, a three-quarter front row (with the reference model beside it for scale), an orthographic side row on a floor grid with 10 cm height ticks, and an optional close-up row; it reads meshopt and WebP. `--yaw` turns the model (180 = its back). A garment layer also gets `tools/check-garment.mjs` (poke-through numbers per clip frame). A passing test is a claim; the picture is the evidence.
- **Timing a hook in the browser:** outside cross-origin isolation Chromium coarsens `performance.now()` to about 0.1 ms, so a per-frame p95 of a 30 us hook reads 0.1-0.2 ms. Serve the capture build with `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (`crossOriginIsolated` turns true, 5 us steps) and report a block mean (30 frames) next to the raw p95. Desktop numbers never stand in for the phone gate.
- **Motion proofs (physics, cloth, anything that moves):** capture a frame burst from headless Playwright, then `node tools/frames-sheet.mjs <out.jpg> <dir> --match ^push --pick 1,4,6,8 --cols 4 --labels --title "..."` for the sheet. Pixel-diff a fixed crop across frames (sharp, mean abs difference) before calling something "moving": a head-on banner that billows toward the camera barely changes its outline.
- **Determinism boundary:** `node tools/import-boundary.mjs <srcRoot> --guard combat,state,content --forbid @react-three/rapier,@dimforge/,physics/` proves no story/save module reaches physics through any chain of relative imports (type-only imports are allowed). Keep a test with a control that the scanner does see the forbidden folder's own imports.
- **Phone:** with USB debugging on (the device owner enables it), use `adb` from the Android SDK `platform-tools`: install, logcat, and frame timing (`dumpsys gfxinfo` for the WebView process). The device owner installs and reports by hand too. Say "device" or "390px emulation" in every result; never mix them.
- **Phone, scripted:** `node tools/phone-perf.mjs --pkg <applicationId> --out <folder outside the repo> --seconds 30 [--perfetto] [--mode android|cdp] [--url <app url>?e2e=1]`. It attaches to the app's WebView (Playwright `_android`, or `adb forward` to `webview_devtools_remote_<pid>` plus `connectOverCDP`), samples rAF frame times (p50/p95/p99), snapshots `window.__gameTest.metrics` when the page was loaded with `?e2e=1`, adds `dumpsys gfxinfo framestats` and battery temperature, and writes PERF.md and PERF.json. `--dry-run` prints the exact adb commands; `selftest` needs no phone. **Precondition, in the game's own debug build:** `WebView.setWebContentsDebuggingEnabled(true)` (Chrome says WebView debugging is not tied to the debuggable flag); the phone awake, USB debugging on, the APK already running. gfxinfo times HWUI frames, not the WebGL canvas, so trust the rAF numbers first. `--perfetto` runs on-device `perfetto` with a config the tool writes next to its output, then pulls `trace.perfetto-trace` for ui.perfetto.dev; the config is a first draft to tune once on a real phone. Not yet run on a real phone: fix the tool when it first meets one. Ask the phone's owner before attaching to it.
- **glTF validation:** `node node_modules/@gltf-transform/cli/bin/cli.js validate <file.glb>` is the Khronos validator ([assets.md](assets.md) step 4 runs it for you). A game's asset test should also fail on `KHR_meshopt_compression` or Draco extensions.
- **Draw calls and triangles per scene:** read `renderer.info` (the e2e hook can expose drawCalls, triangles, textures and geometries in `metrics`). For an on-screen readout use stats-gl in debug builds only: pin `stats-gl@4.2.3` as a devDependency in the game and mount it like this (React Three Fiber; Vite strips the branch from release builds because `VITE_PERF` is unset there):
  ```tsx
  // src/game/PerfStats.tsx
  import { useEffect, useRef } from 'react'; import { useThree, useFrame } from '@react-three/fiber';
  export default function PerfStats() {
    const gl = useThree(s => s.gl), stats = useRef<any>(null);
    useEffect(() => { let alive = true, s: any;
      import('stats-gl').then(({ default: Stats }) => { if (!alive) return; s = new Stats({ trackGPU: false }); document.body.appendChild(s.dom); s.init(gl); stats.current = s; });
      return () => { alive = false; s?.dom.remove(); stats.current = null; }; }, [gl]);
    useFrame(() => stats.current?.update());
    return null;
  }
  // in the scene file
  import { lazy, Suspense } from 'react';
  const PerfStats = import.meta.env.VITE_PERF === '1' ? lazy(() => import('./PerfStats')) : null;
  // inside <Canvas>:  {PerfStats && <Suspense fallback={null}><PerfStats /></Suspense>}
  // debug APK build only:  VITE_PERF=1 npm run build
  ```
  GPU timer queries (`trackGPU: true`) are often missing on Android WebView, so keep it false there and read CPU frame time.
- **Delegated results:** re-run a delegate's key checks yourself before reporting them.
- **Realism lookdev (game frame vs real photo):** `node tools/lookdev-compare.mjs <pairs.json> <outDir>` (the header documents the pairs format; `selftest`). It compares ROI **ratios** (lit:shade, sky:ground, wb, Michelson, clipping), never absolute pixels, writes a sheet per pair (photo | game, ROI boxes, histograms, metric table) plus REPORT.md. The game side must freeze the camera, hide the HUD and offer light isolation (sun-only, ambient-only frames) and a grey-card chart. Calibrate exposure on the 18% card first (sRGB 118 +- 6).
- **Frame gate:** `node tools/learn/frame-gate.mjs <boxes.json> <baseline-dir> <candidate-dir>` measures box luma/hue/chroma/ratio numbers of candidate frames against the last accepted ones and exits 1 outside tolerance: numbers before eyes.
