# Blender: procedural geometry (buildings, walls, props)

Use a portable **Blender 4.5 LTS** (Windows x64 zip from download.blender.org; check the SHA-256 against the official `.sha256` file) unzipped into `bin/blender/` (git-ignored, not installed, not on PATH or in the registry), or point `STUDIO_BLENDER` at any `blender.exe`. Licence: GPL. Blender is a tool only, and what it outputs is yours (register outputs as `OWN`).

Reinstall: download the `blender-4.5.x-windows-x64.zip` and the `.sha256` file from `https://download.blender.org/release/Blender4.5/`, compare the hashes, unzip into `bin/blender`, then run `node tools/blender-run.mjs selftest`.

1. **Run scripts** with `node tools/blender-run.mjs <script.py> [--timeout s] [--log file] -- <args>`. It runs `--background --factory-startup --python-exit-code 1`, so a Python error fails the run, and it keeps the log. The first start after install can take a minute (antivirus scan); later starts take a few seconds.
2. **Kit generators** are in `blender/`:
   - `kitlib.py`: authoring in game coordinates (y up), world-scale box UVs per material slot, bevels, sharp-by-angle plus weighted normals, baked vertex shade, GLB export.
   - `medieval_kit.py`: house (timber frame, jetty, slate roof with courses, chimney, windows with shutters, recessed door), curtain wall, low wall, tower and gatehouse, well, stall, cart and wagon.
   - Game parameters stay in your game repo, as a JSON file with the slots, units (metres per texture repeat, as the game's box UVs), shades, bevels, weathering and pieces.
   - Build with `node tools/blender-run.mjs blender/medieval_kit.py -- <params.json> <rawDir> [ids]`. It writes `<id>.glb` with `<id>_LOD0` / `<id>_LOD1` nodes (variants: `<id>_v<n>_LOD<k>`), one mesh per material slot named after the slot, plus `kit-report.json` (triangles per LOD and slot) and `kit.blend`.
3. **Optimize** with `node tools/optimize-gltf.mjs <raw>.glb <game>/public/assets/<dir>/<id>.glb --profile static --keep-nodes 1`. `--keep-nodes` is required: without it, flatten+join merge LOD0 into LOD1, and attribute pruning drops the UVs of texture-less materials. The game then assigns its own tuned materials by slot name, and the vertex colour carries the shade.
4. **Review in Blender**: `node tools/blender-run.mjs blender/render_views.py -- <rawDir>/kit.blend <review.json> <outDir> <id>`. Pass **one id per run**: a long EEVEE loop crashed Blender (exit 255) after about 9 renders. It renders an LOD0 three-quarter view, a street-level view (eye 1.6 m) and an LOD1 view with the game's colour textures. Then run `frames-sheet.mjs` with the reference photo as the first tile.
5. **Review in the game renderer** (the real judge). Build the client to your own outDir, then inject the GLBs into the running game. No `src/` edit is needed: three's `__THREE_DEVTOOLS__` 'observe' event hands you the Scene (define it in `addInitScript`). Load the GLBs with three's GLTFLoader (served with bare `'three'` imports rewritten). Swap in the game's materials by name and hide the old groups. Shoot before and after at noon and dusk.
6. **Integrate in the game.** One three `LOD` per piece: bake each level to **one mesh per game material** (dequantise the KHR-quantized attributes to Float32 first, then apply node and placement matrices; slots that share a material merge). A straight wall run is one LOD with all its segments merged, placed at the run's centre, with the LOD1 distance plus half the run length, so its near end never drops to LOD1 early. Mark the LOD0 meshes `noCameraCollide` and let the hidden LOD1 meshes be the camera colliders (raycasts ignore visibility and LOD1 is 5-20x fewer triangles). Physics keeps simple boxes. Then raycast from the player's eye at every door and arch of the kit and look at a close crop of each opening in the real game frame: mortar gaps through a hollow shell show sky, and a foot or plinth can wall up a door.
7. **Budget**: up to about 3-6k triangles per building at LOD0, LOD1 under about 1.5k. Bevel only the edges that catch light: the long edges of beams, the top edges of stones, the vertical edges of quoins and corbels. Masonry courses use `top_inset`, so each bed joint is a thin shadow line under the next course. A stepped course reads as a bright seam.

## Realistic humans with MPFB2

MPFB 2.0.18 (MakeHuman for Blender; plugin GPLv3, assets and outputs CC0, no claim on outputs) is installed as a **user extension in the portable config** (`bin/blender/portable/`, a folder next to `blender.exe` that makes Blender portable; nothing touches the system). Reinstall: get `add-on-mpfb-v<ver>.zip` from the extensions.blender.org API listing (`/api/v1/extensions/?id=mpfb`, `archive_url` and `archive_hash`), check the sha256, then `blender.exe --background --factory-startup --command extension install-file -r user_default --enable <zip>`; unzip the CC0 asset packs from `static.makehumancommunity.org/assets/assetpacks/` into `portable/extensions/.user/user_default/mpfb/data` (keep a list of the packs and their hashes). Scripts enable it with `bpy.ops.preferences.addon_enable(module='bl_ext.user_default.mpfb')`.
1. **Build** with `node tools/blender-run.mjs blender/mpfb_character.py -- <spec.json> <outDir> render|game` (spec: macro sliders, race, skin `.mhmat`, eyes, brows, lashes, hair, clothes by file name with extension, `skin_group` node values, `tints`, `garments` tabard/cloak, `clips` idle and walk FBX). `render` keeps the SSS skin for Cycles and poses the arms from the idle clip; `game` strips helper geometry, culls body faces under clothes, retargets the clips onto MPFB's Mixamo rig (bone names `mixamorigX`, clips `Idle_A`, `Walking_A`) and writes `<name>.glb` (then `optimize-gltf.mjs --profile skinned`).
2. **Look**: `blender/people_render.py -- <name>-render.blend <outDir> front,three,face,face3 noon,dusk [samples] [px]` (Cycles, Nishita sky, game-like sun) and `tools/render-people-ingame.mjs <glb> <outDir>` (three.js with NOON/DUSK lighting rows you copy from your game). Compare against `render-people-ingame.mjs` on an existing character GLB in the same light.
3. Keep `detailed_helpers=True` and `mask_helpers=True` when building: the Mixamo rig fits its bones to the joint helper groups, and the mask hides the helper mesh.
